# 知识库 JSON 规范（写作代理必读）

目录：`<仓库根>\data\knowledge\`
每个写作代理产出一个文件：`<组名>.json`，UTF-8，**只放一个 JSON 对象**，不要 markdown 代码围栏、不要注释。

## 顶层结构

```json
{
  "group": "组名，如 beethoven-symphonies",
  "albums": [ ... ],
  "works":  [ ... ]
}
```

## albums[] —— 一张唱片/一个版本写一条

```json
{
  "name": "专辑文件夹名，必须与音乐库里的文件夹名逐字一致",
  "composer": "作曲家或艺人（用于目录分类，中文名+原文，如 贝多芬 Beethoven）",
  "era": "baroque|classical|romantic|modern|russian|chinese|pop|folk|mixed",
  "performer": "指挥/演奏/乐团（一行）",
  "recorded": "录音年份或年代，如 1961–62（不确定写「约1962」）",
  "released": "本文件夹所对应的发行/转制年份，如 2016（DG 24-96 重制）",
  "label": "厂牌，如 DG / Decca / Philips / Melodiya",
  "edition": "这一版是什么版本，如「DG 2016 24bit/96kHz 数字重制」「Esoteric 2015 SACD」「日本天龙1MM1首版」",
  "oneliner": "一句话定位，20–40 字，让人一眼知道这版好在哪",
  "version_notes": [
    {"h": "录音与阵容", "t": "60–200 字"},
    {"h": "版本与转制", "t": "60–200 字：这份文件是哪个母带/转制，规格如何"},
    {"h": "听感与特色", "t": "60–200 字：声音特点、演绎取向、与同曲其他名版的差别"},
    {"h": "收藏与使用", "t": "40–150 字：值不值得留、适合什么场景、有没有短板"}
  ],
  "rating": 1,
  "tags": ["可听入门", "参考级演绎", "发烧录音", "历史文献", "同曲首选"],
  "track_notes": {"曲名或序号": "一句话说明（仅歌曲/合集类专辑需要）"}
}
```

- `rating`：1–5，5 = 该曲目在库内的首选版本。**不要都给 4、5**，要拉开差别。
- `tags` 从上面括号里的词表里挑，1–4 个。
- `track_notes`：仅当专辑是歌曲/合集/试音碟（非古典套曲）时提供，键用实际曲名（从 inventory.json 取，逐字一致）。
- `track_works`（可选）：当音轨标题里看不出作品名、只能靠顺序判断时（例如标题只有「I - Allegro」或只有曲目号），
  给一个与全专辑音轨顺序一一对应的作品 id 数组，如 `["beethoven-pc5","beethoven-pc5","beethoven-pc5"]`，
  不确定的位置填 `""`。渲染器会用它把音轨锚回作品，再按顺序对齐乐章。
- 不确定的事实（录音日期、制作人、具体转制工艺）宁可不写或写「约」，**绝不编造**唱片编号、制作人姓名。

## works[] —— 作品级知识（曲目讲解的来源）

```json
{
  "id": "beethoven-sym5",
  "composer": "贝多芬 Beethoven",
  "title": "c小调第五交响曲「命运」Op.67",
  "aka": ["Symphony No.5", "Symphonie Nr. 5", "第五交响曲"],
  "match": ["symphon\\w*.{0,14}\\b5\\b.{0,24}op\\.?\\s*67", "第五交响曲"],
  "about": "150–300 字：创作背景、音乐内容、听点、在音乐史上的位置",
  "movements": [
    {"n": 1, "name": "Allegro con brio", "about": "50–150 字：这一乐章讲了什么、听什么"}
  ]
}
```

- `match`：**大小写不敏感的正则**，用来匹配音轨标题（音轨标题来自文件标签，可能是英文/德文/中文）。
  写 2–4 条，一条命中即可。宁可宽松一点，也别太宽（如 `op\.?\s*67` 会误伤其他作品）。
- `movements[].n`：乐章号（阿拉伯数字）。渲染器会用两种办法对上：
  1) 音轨标题开头的编号（`I.` `1.` `第一乐章`）；
  2) 在同一作品内按顺序依次对齐。
  所以**乐章条目必须按演出顺序排列，数量与常见版本一致**。
- 只写这张专辑里真正出现的作品；同一作品在多张专辑里出现时，条目写一次就够（重复的会自动合并）。
- 单乐章作品（序曲、交响诗、协奏曲单章、歌曲、舞曲）`movements` 留空数组 `[]` 即可。

## 文体要求

- 中文简体，专业但不端着；具体、有事实、有判断；不写「震撼人心」「不可错过」这类空话。
- 讲作品时讲**音乐本身在干什么**（结构、主题、调性、配器、情绪走向、首演轶事），不要复述曲名。
- 讲版本时讲**这一版与别的版的差别**（速度、句法、乐团音色、录音空间感、转制得失）。
- 长句拆短。允许用中文书名号、引号。

## 校验

写完后自己跑一遍：

```powershell
python -c "import json;d=json.load(open(r'<你的文件>',encoding='utf-8'));print(len(d['albums']),len(d['works']))"
```

确认能解析、专辑名与文件夹名逐字一致。
